## 一、项目说明

> 性能实测与完整测试用例详见《06-性能实测与测试说明》：冷启动均值 246ms（onCreate→首帧）、RAG 热查询 3-6s（断网降级 <0.1s）、运行内存 RSS ≈37MB、14 项功能用例全部通过。

### 1.1 项目背景与定位

我国 60 岁以上人口已超 3.1 亿（国家统计局 2024 年数据），独居与空巢老人家庭占比持续上升。跌倒是我国 65 岁以上老年人因伤致死的首位原因；同时多病共存带来的用药安全问题（重复用药、禁忌联用、漏服）常年被低估。现有方案要么依赖摄像头监控（老人抗拒、隐私泄露风险），要么依赖单一手环报警（误报率高、老人忘戴、数据全部上云）。

**银龄守护**面向独居老人的"跌倒、用药、慢病"三大风险，构建**端侧隐私感知 + 云端智能决策 + 分布式家人协同**的守护闭环：

- **端侧隐私感知**：加速度传感器与麦克风原始数据全程不出设备，仅结构化的告警事件外发——"数据不动、结论出行"；
- **云端智能决策**：用药安全 RAG 问答（检索增强生成，答案可溯源），断网自动降级本地知识库；
- **家人协同**：家属端实时看板 + 系统级告警通知 + 桌面元服务卡片。

### 1.2 目标用户

| 角色 | 画像 | 核心诉求 |
|---|---|---|
| 老人（王奶奶，72 岁，独居，高血压 + 2 型糖尿病） | 智能手机使用不熟练，视力/记忆力衰退 | 摔倒有人知道；吃药不出错；操作极简 |
| 子女（王先生，45 岁，上班族，异地工作） | 无法贴身照料，长期处于"未知焦虑" | 实时掌握状态；紧急情况第一时间知情并响应 |

> **画像来源说明**：上述画像基于团队成员自身的异地家庭真实场景（父母在老家、成员在外求学）与公开统计数据构建，并将在试点阶段开展正式用户访谈与问卷验证后迭代。

### 1.3 核心功能

1. **端侧跌倒检测与倒计时自救**：加速度合幅值"冲击相 + 静止相"状态机端侧判定；触发后全屏高唤醒告警页 10 秒倒计时——老人点击"我没事"即解除（抑制误报），无响应则自动升级并通知家属（兜底真跌倒）；
2. **语音求救识别**：端侧短语音识别 + 求救词系统热词（"救命/摔倒了"等），覆盖传感器未达阈值或老人无法触屏的场景；
3. **AI 用药安全问答（RAG）**：本地药师知识库检索 + 云端大模型生成通俗回答，答案附知识来源可核验；云端不可用自动降级本地直答；
4. **家属守护看板**：实时状态（守护开关/心率/步数/用药完成度）+ 告警记录全生命周期（确认中→待处理→已处理）+ 回拨/标记处理；
5. **系统级告警通知与桌面卡片**：告警升级发布系统通知（应用后台可见）；家属桌面元服务卡片实时显示老人状态摘要；
6. **数据持久化**：告警事件 RelationalStore 落库，应用重启/进程被杀后完整恢复。

### 1.4 使用场景与核心流程（场景故事板）

**S1 跌倒告警闭环（主场景）**
奶奶起夜摔倒 → 手机端侧判定"冲击 + 持续静止" → 全屏红色倒计时 10 秒 →（a）奶奶清醒点"我没事"，事件解除并记录响应时长；（b）无响应 → 事件升级，系统通知弹出、家属看板出现红色待处理告警（可回拨/标记处理）。全过程原始加速度数据不出手机。

**S2 用药安全问答**
奶奶拿到新药，问"这个药和降压药能一起吃吗？" → 系统检索本地知识库命中"联用原则"等条目 → 云端 GLM 基于条目生成口语化回答（≤150 字，结尾"遵医嘱"）→ 答案下方标注知识来源。

**S3 家属日常查看**
王先生午休打开看板：守护中绿标、心率/步数实时、今晨奶奶自己解除过一次跌倒提醒的记录一目了然 → 安心。

### 2.2 AI 能力融合清单

| AI 能力 | 形态 | 落地 |
|---|---|---|
| 端侧跌倒检测 | "冲击相(>2.8g) + 静止相(<0.25g×12帧)"滑动窗口状态机，30s 冷却防重报 | FallDetectService.ets（真机验证） |

| 云端大模型 RAG 问答 | 智谱 GLM（glm-4-flash）；**GLM embedding-2 向量召回（余弦相似度 Top3）**，关键词检索为降级路径；命中条目上下文注入→受控生成（仅基于条目/不编造/≤150字/遵医嘱结尾）；答案附来源（Self-RAG 式可溯源） | LlmService.ets（真机验证，含语义召回实证） |

| 用药管家 Agent（AI 工作流） | ReAct 式多步编排：GLM 将自然语言目标规划为多检索主题→逐主题向量检索去重→多主题综合生成；"分析/检索计划/知识检索/生成"过程步骤在对话流实时可视化 | AgentService.ets（真机验证：多主题来源聚合 6 条 vs 单问 3 条） |
| 多模态融合决策 | 加速度（冲击+静止）× 语音（求救关键词）× 视觉（识药）三模态，统一事件模型 | GuardStore 统一事件模型 |

## 三、创新点说明（六维度）

1. **AI 应用创新——端侧热词求救识别**：将"救命/摔倒了"注册为系统热词的端侧识别方案，在不联网、语音原文不出设备的前提下实现语音呼救；与加速度检测构成双模态互补（覆盖缓慢滑倒与无法触屏两类传感器盲区）。
2. **场景创新——倒计时自救机制**：10 秒倒计时把"误报骚扰"与"漏报风险"的矛盾转化为可交互的确认流程——老人一键自救，无响应自动升级。演示中两类路径均可复现。
3. **产品创新——单应用双角色**：老人端/家属端共用一个应用两种工作台，降低安装与理解成本，同时天然适配分布式同应用数据同步框架。
4. **技术创新——端云协同隐私架构**：传感与语音原始数据端侧处理、仅结构化事件外发；RAG 云端生成 + 三级降级（云端→本地库→离线提示）保证演示与弱网可用；告警事件按 id 幂等合入，跨设备与本地持久化双链路一致。
5. **商业模式创新——社区共担订阅**：面向子女的家庭订阅（基础守护免费 + 增值服务订阅），叠加社区养老服务中心批量采购（政府购买服务/长护险试点场景），详见落地规划。
6. **用户体验创新——适老化全链路**：正文 24fp 起、按钮高度 84vp 起、高对比暖色系、语音免打字问答、全流程零层级（一步直达）；家属端则信息密度优先（三色状态徽章、一屏总览）。

### 4.3 ArkTS/ArkUI 实现要点

- **响应式刷新模式**：标量状态（心率/步数/守护开关/告警版本号）走 `AppStorage` + 页面 `@StorageProp` 订阅；列表类（告警）以版本号 `@StorageProp @Watch` 触发快照刷新（`alertsSnap = store.alerts.slice()`）——解决了 ForEach/空态对普通数组变更不响应的问题；
- **适老化设计规范常量化**（Theme.ets）：字号/色彩统一管理，老人端与家属端两套规范；
- **权限最小化**：全部权限附用途文案；麦克风/分布式权限运行时申请，拒绝不阻塞主流程；
- **ArkTS 卡片受限环境适配**：卡片仅用基础组件 + LocalStorageProp 绑定，点击 postCardAction 路由回应用。

### 4.4 难点与解决方案

| 难点 | 解决方案 | 效果 |
|---|---|---|
| 误报与漏报矛盾 | 倒计时自救交互（创新点 2） | 演示两类路径均闭环 |
| 云端大模型演示稳定性 | 三级降级：GLM→本地知识库→离线提示 | 弱网/断网演示不翻车 |
| 本地模拟器不支持分布式组网（实证：DeviceManager 信任列表为空、DSoftbus 发现为空） | 同步层完整实现 + 优雅降级（无组网自动纯本机）；文档明确真机部署路径（同账号+同应用+同局域网） | 单机演示完整，真机即启用 |
| 通知授权弹框被遮挡导致通知"失灵" | onForeground 请求授权 + 授权状态前置检查 | 通知链路稳定 |

### 4.5 联邦学习演进路线的模拟实证

针对跌倒检测从阈值状态机向轻量模型演进的关键问题——**单家庭样本稀少（跌倒是小概率事件）与隐私约束（原始传感数据不可出户）的矛盾**，我们用模拟实验验证了 FedAvg 联邦聚合的收益（实验脚本 `tools/fedavg_sim.py`，结果图 `docs/assets/fedavg-simulation.svg`）：

- 设定：10 个模拟家庭（各自存在设备佩戴与活动习惯导致的特征分布偏移），每家仅 30 条小样本（含 5% 标注噪声与类间重叠），本地模型为逻辑回归；
- 结果：**单家庭独立训练平均准确率 80.8%（最差家庭仅 67.5%）；FedAvg 联邦聚合 30 轮后收敛至 85.9%，几乎追平"所有数据集中训练"的隐私上界 86.4%**；
- 结论：各家庭仅上传本地模型参数（梯度聚合，原始数据全程不出设备），即可获得接近全局数据集的模型收益，且对数据条件最差的家庭提升最大——**在"数据永不出户"的隐私约束下逼近集中式训练的性能上界（85.9% vs 86.4%）**，这正是本作品"阈值 → 轻量时序模型 → 联邦学习"演进路线的方法学依据。

## 七、落地规划

### 7.1 推广与用户增长

> 需求验证现状：本作品需求假设来自团队自身异地家庭场景与公开统计数据（老龄化规模、跌倒致死顺位、居家养老政策方向），正式用户调研已列入试点阶段第一项工作。

- **冷启动**：与 2~3 个社区养老服务中心共建试点（免费部署老人端 + 培训社工），以"社区背书"获取首批 500 个家庭；配合社区义诊/防跌倒讲座做地推转化；
- **增长闭环**：子女端"守护周报"（每周老人健康摘要）自带分享属性；老用户邀请子女配偶/兄弟姐妹加入同一守护圈形成家庭网络效应；
- **院校合作**：高校志愿服务团队"一对一"结对独居老人安装辅导（已具备演示条件，可立即启动）。

### 7.2 商业闭环

| 层级 | 内容 | 定价思路 |
|---|---|---|
| 免费层 | 跌倒检测、用药提醒、本地知识库问答 | 获客与公益背书 |
| 订阅层（子女付费） | 云端 RAG 问答、历史报告、多子女协同、系统通知增强 | 9.9 元/月 家庭卡 |
| 机构层 | 社区/养老机构批量看板、社工工单、数据大屏 | 按床位年费，对接政府购买服务与长护险试点 |

> 机构层是商业可持续的关键：民政部门"居家养老适老化改造"与政府购买服务预算是社区批量部署的现实资金来源，本项目"端侧隐私优先"的架构恰好契合政府采购对数据不出域的合规要求，是区别于纯云端竞品的采购优势。

### 7.3 运营机制与迭代方向

- **近期（1~3 月）**：应用市场上架（已具备签名与权限合规基础）；Call Kit 回拨打通；穿戴设备（手环/手表）真实心率接入多模态融合；用药知识库扩充至 500+ 条并引入药师审核流程；
- **中期（3~6 月）**：跌倒检测从阈值状态机升级为轻量时序模型（1D-CNN 端侧推理），并按联邦学习（FedAvg）范式跨家庭联合优化——各家庭端侧本地训练、仅上传梯度聚合，在"数据永不出户"约束下持续降低误报率；
- **长期**：接入社区养老服务平台生态，形成"家庭守护—社区响应—机构服务"三级网络。

### 7.4 社会价值

面向积极应对人口老龄化国家战略，以"隐私优先的适老科技"弥合数字鸿沟：老人零学习成本获得 AI 守护，子女以最低打扰获得确定性安心，社区获得可持续的服务抓手。
